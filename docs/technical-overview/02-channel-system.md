## 🎯 问题：每个平台都不一样

让我们看看各个聊天平台有多"个性"：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        各平台の小脾气                                │
├──────────┬──────────────────────────────────────────────────────────┤
│ WhatsApp │ • 用手机号识别用户                                        │
│          │ • 消息长度限制 4000 字符                                   │
│          │ • 需要扫码登录                                            │
├──────────┼──────────────────────────────────────────────────────────┤
│ Telegram │ • 用 chat_id 识别用户                                     │
│          │ • 支持 Markdown 格式                                       │
│          │ • 需要 Bot Token                                          │
├──────────┼──────────────────────────────────────────────────────────┤
│ Discord  │ • 有服务器(Guild)的概念                                   │
│          │ • 消息长度限制 2000 字符                                   │
│          │ • 需要 Bot Token + OAuth                                  │
├──────────┼──────────────────────────────────────────────────────────┤
│ Slack    │ • 有工作空间(Workspace)的概念                             │
│          │ • 支持 Block Kit 富文本                                    │
│          │ • 需要 App + Bot Token                                    │
├──────────┼──────────────────────────────────────────────────────────┤
│ Signal   │ • 端到端加密                                              │
│          │ • 用手机号识别                                            │
│          │ • 需要注册设备                                            │
└──────────┴──────────────────────────────────────────────────────────┘
```

如果直接写代码，会变成这样：

```typescript
// ❌ 噩梦般的代码
if (platform === 'whatsapp') {
  // 100 行 WhatsApp 特定代码
} else if (platform === 'telegram') {
  // 100 行 Telegram 特定代码
} else if (platform === 'discord') {
  // 100 行 Discord 特定代码
} else if (platform === 'slack') {
  // 100 行 Slack 特定代码
}
// 每加一个平台，这里就要改一次... 崩溃 💀
```

## 💡 解决方案：适配器模式

OpenClaw 的做法是定义一个**统一接口**，每个平台实现自己的**适配器**：

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│                        🎛️ OpenClaw 核心                             │
│                                                                     │
│     只认识这个统一接口：                                              │
│     ┌─────────────────────────────────────────┐                     │
│     │  interface ChannelPlugin {              │                     │
│     │    sendMessage(text)    // 发消息       │                     │
│     │    receiveMessage()     // 收消息       │                     │
│     │    getUser()            // 获取用户     │                     │
│     │  }                                      │                     │
│     └─────────────────────────────────────────┘                     │
│                            ▲                                        │
│                            │                                        │
│         ┌──────────────────┼──────────────────┐                     │
│         │                  │                  │                     │
│         ▼                  ▼                  ▼                     │
│   ┌──────────┐      ┌──────────┐      ┌──────────┐                 │
│   │ WhatsApp │      │ Telegram │      │ Discord  │    ...更多      │
│   │ Adapter  │      │ Adapter  │      │ Adapter  │                 │
│   └──────────┘      └──────────┘      └──────────┘                 │
│         │                  │                  │                     │
│         ▼                  ▼                  ▼                     │
│   ┌──────────┐      ┌──────────┐      ┌──────────┐                 │
│   │ Baileys  │      │  grammy  │      │ discord  │    各平台の     │
│   │   SDK    │      │   SDK    │      │   SDK    │    官方 SDK     │
│   └──────────┘      └──────────┘      └──────────┘                 │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

这样，核心代码就变简单了：

```typescript
// ✅ 优雅的代码
async function handleMessage(channel: ChannelPlugin, message: string) {
  const response = await ai.chat(message);
  await channel.sendMessage(response);  // 不管是什么平台，调用方式一样！
}
```

## 🧩 Channel 的七大"器官"

每个 Channel 适配器需要实现这些功能模块：

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│                   🔌 ChannelPlugin 的七大器官                        │
│                                                                     │
│  ┌─────────────────────────────────────────────────────────────┐   │
│  │                                                             │   │
│  │  1️⃣  ConfigAdapter        账户配置管理                       │   │
│  │      "我是谁？我的 Token 是什么？"                            │   │
│  │                                                             │   │
│  │  2️⃣  OutboundAdapter      消息发送                          │   │
│  │      "怎么把消息发出去？"                                     │   │
│  │                                                             │   │
│  │  3️⃣  GatewayAdapter       消息接收                          │   │
│  │      "怎么监听新消息？"                                       │   │
│  │                                                             │   │
│  │  4️⃣  SecurityAdapter      权限控制                          │   │
│  │      "这个人有权限跟我聊天吗？"                               │   │
│  │                                                             │   │
│  │  5️⃣  GroupAdapter         群聊行为                          │   │
│  │      "群里消息怎么处理？要 @我 吗？"                          │   │
│  │                                                             │   │
│  │  6️⃣  MentionAdapter       @提及处理                         │   │
│  │      "有人 @我 了！"                                         │   │
│  │                                                             │   │
│  │  7️⃣  ThreadingAdapter     线程/回复                         │   │
│  │      "这条消息是回复哪条的？"                                 │   │
│  │                                                             │   │
│  └─────────────────────────────────────────────────────────────┘   │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

用表格再看一遍：

| 适配器 | 职责 | 举例 |
|--------|------|------|
| ConfigAdapter | 账户管理 | Token 存储、多账号支持 |
| OutboundAdapter | 发消息 | 文本、图片、文件发送 |
| GatewayAdapter | 收消息 | Webhook、轮询、WebSocket |
| SecurityAdapter | 权限控制 | 白名单、黑名单 |
| GroupAdapter | 群聊逻辑 | 是否需要 @、谁能触发 |
| MentionAdapter | @处理 | 检测和解析 @mention |
| ThreadingAdapter | 线程回复 | 回复特定消息 |

## 💡 设计启示

这个设计模式叫做 **适配器模式（Adapter Pattern）**，它的核心思想是：

> **定义统一接口，让不兼容的东西可以一起工作**

就像：
- 🔌 万能充电器：一个接口，充所有手机
- 🎧 蓝牙适配器：让有线耳机变无线
- 🌐 API 网关：统一的入口，后面接各种服务
