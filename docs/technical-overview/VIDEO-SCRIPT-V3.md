## A-ha #1："我没问它，它居然主动找我"（1:00 - 8:00）

### 体验

**【画面：展示手机通知】**

早上 9 点，我还没起床。

手机响了：

> "早上好！今天有 3 件事需要你关注：
> 1. 下午 2 点和张总的会议
> 2. 那个 Bug 修复的 PR 还没 review
> 3. 你答应帮小王看的文档"

我没有设闹钟，没有问它"今天有什么安排"。

**它自己知道要提醒我。**

### 这是怎么做到的？

**【画面：代码 + 流程图】**

答案藏在一个叫 **Heartbeat（心跳）** 的机制里。

```typescript
// 每 30 分钟，系统会"戳"一下 AI
const HEARTBEAT_PROMPT =
  "检查一下有没有什么需要告诉用户的。" +
  "如果没有，就回复 HEARTBEAT_OK。";
```

但关键在于下一步：

```typescript
// AI 回复了 "HEARTBEAT_OK"？
if (response.includes("HEARTBEAT_OK")) {
  // 什么都不做，不打扰用户
  return;
}

// AI 说有事？发消息！
await sendToUser(response);
```

**【画面：流程图动画】**

```
每 30 分钟
    ↓
问 AI："有事吗？"
    ↓
   ┌─────────────────┐
   │  AI 判断       │
   └────────┬────────┘
            │
    ┌───────┴───────┐
    ↓               ↓
  没事            有事
    ↓               ↓
 静默丢弃      发消息给用户
```

**【稍作停顿】**

这个设计的精妙在于：

**AI 自己决定要不要打扰你。**

不是定时发消息骚扰你，而是定时**问 AI 要不要发消息**。

如果 AI 觉得没什么重要的，它就说 "HEARTBEAT_OK"，系统就把这条回复扔掉，你完全不知道这次心跳发生过。

### 更进一步：HEARTBEAT.md

**【画面：展示文件内容】**

那 AI 怎么知道要关注什么？

你可以写一个 `HEARTBEAT.md` 文件：

```markdown
# 心跳检查清单

- 看看日历有没有今天的会议
- 检查有没有重要邮件没回
- 如果是早上，问候一下用户
- 如果用户提过什么待办，提醒一下
```

每次心跳，AI 都会读这个文件。

**你通过一个文本文件，就能控制 AI 关注什么。**

## A-ha #2："我在 WhatsApp 问，它记得 Telegram 聊的"（8:00 - 15:00）

### 体验

**【画面：两个聊天界面并排】**

昨天在 Telegram 上：

> 我：我最近在学 Rust
> AI：Rust 是个很棒的选择！它的所有权系统...

今天在 WhatsApp 上：

> 我：有什么学习资源推荐吗？
> AI：关于 Rust 的学习资源，我推荐...

等等。

**我没说是 Rust 的学习资源。但它知道。**

它记得我昨天在**另一个平台**聊的内容。

### 这是怎么做到的？

**【画面：Session 结构图】**

答案是 **Session（会话）** 系统。

```
~/.openclaw/sessions/

agent:main:telegram:123456.json   ← Telegram 对话
agent:main:whatsapp:+86138xxx.json ← WhatsApp 对话
```

但这不够。如果每个平台的对话是独立的，它怎么能"跨平台记忆"？

答案是 **Memory 系统**。

**【画面：三层记忆架构】**

```
┌─────────────────────────────────────┐
│  Layer 1: Session                   │
│  当前对话的上下文                    │
│  （每个平台独立）                    │
└─────────────────────────────────────┘
          ↓ 不够？往下找
┌─────────────────────────────────────┐
│  Layer 2: Workspace Files           │
│  AGENTS.md, 笔记, 任何 .md 文件     │
│  （跨平台共享）                      │
└─────────────────────────────────────┘
          ↓ 还不够？往下找
┌─────────────────────────────────────┐
│  Layer 3: Vector Memory             │
│  所有历史对话的语义索引              │
│  （可以搜索"我之前学什么来着"）      │
└─────────────────────────────────────┘
```

**【画面：代码展示】**

```typescript
// src/memory/manager.ts

// 混合搜索：关键词 + 语义
const results = mergeHybridResults(
  searchKeyword(query),  // "Rust" 精确匹配
  searchVector(query)    // "编程语言学习" 语义相似
);
```

所以当你问"学习资源"时，AI 会：

1. 先看当前对话（WhatsApp）——没提到 Rust
2. 再搜索 Memory——发现昨天 Telegram 聊过 Rust
3. 把相关记忆注入上下文
4. 回答时就"记得"了

**这就是为什么它能跨平台记忆。**

## A-ha #3："我让它发消息，它真的发了"（15:00 - 22:00）

### 体验

**【画面：聊天记录】**

> 我：帮我问一下老王明天有没有空
> AI：好的，我已经给老王发送了消息："明天有空吗？方便的话想约你聊聊。"

我切换到老王的对话，发现**真的有一条消息发过去了**。

不是 AI 帮我"生成"消息让我复制粘贴。

**是它直接发了。**

### 这是怎么做到的？

**【画面：Tool Use 流程】**

这是现代 AI 的一个重要能力：**Tool Use（工具调用）**。

```typescript
// 告诉 AI 它有哪些工具
const tools = [
  {
    name: "send_message",
    description: "发送消息给指定联系人",
    parameters: {
      target: "联系人名字或手机号",
      text: "消息内容"
    }
  }
];
```

当 AI 决定要用工具时，它不会直接回复你，而是返回：

```json
{
  "tool": "send_message",
  "parameters": {
    "target": "老王",
    "text": "明天有空吗？方便的话想约你聊聊。"
  }
}
```

**【画面：执行流程动画】**

```
你："帮我问老王明天有没有空"
        ↓
    AI 思考...
        ↓
    AI 决定调用工具
        ↓
┌─────────────────────────────────────┐
│  OpenClaw 收到工具调用请求           │
│  1. 找到"老王"的联系方式            │
│  2. 通过 WhatsApp Channel 发送消息  │
│  3. 返回结果给 AI                   │
└─────────────────────────────────────┘
        ↓
    AI 生成最终回复
        ↓
"好的，我已经给老王发送了消息..."
```

**【稍作停顿】**

这就是 AI 从"聊天机器人"变成"助手"的关键。

聊天机器人只能**说**。
助手可以**做**。

Tool Use 让 AI 有了"手"。

## A-ha #4："5 个人同时问，它没有乱"（22:00 - 28:00）

### 体验

**【画面：多个聊天窗口同时活跃】**

有一次我在测试。

- WhatsApp 群里有人问问题
- Telegram 私聊来了一条消息
- 同时心跳触发了
- 还有一个定时任务在跑

我以为它会崩溃，或者回复会乱掉。

**结果每个对话都正常，没有串。**

### 这是怎么做到的？

**【画面：车道系统】**

答案是 **Lane（车道）** 系统。

```typescript
// src/process/lanes.ts

export const enum CommandLane {
  Main = "main",        // 用户对话
  Cron = "cron",        // 定时任务
  Subagent = "subagent", // 子任务
  Nested = "nested",     // 嵌套调用
}
```

**【画面：高速公路动画】**

想象一条高速公路：

```
用户消息 ─────→ [Main 车道] ────→
                                  ↘
定时任务 ─────→ [Cron 车道] ────→   Agent
                                  ↗
心跳检查 ─────→ [Main 车道] ────→
```

规则：
- **同一车道内**：必须排队（串行）
- **不同车道间**：可以并行

为什么这样设计？

**因为同一个用户的消息需要保持顺序**——你说的第一句话必须在第二句话之前处理，否则上下文就乱了。

但定时任务和用户对话**可以同时进行**——它们是独立的。

**【画面：代码展示】**

```typescript
// 每个车道有自己的并发限制
setCommandLaneConcurrency(CommandLane.Main, 1);  // 串行
setCommandLaneConcurrency(CommandLane.Cron, 1);  // 串行
```

这是一个经典的工程权衡：

**在正确的粒度上加锁。**

太粗（全局锁）→ 性能差
太细（不加锁）→ 会出 bug
刚好（按车道锁）→ 既安全又高效

## A-ha #5："我换了个平台，配置不用改"（28:00 - 34:00）

### 体验

**【画面：添加新平台的过程】**

一开始我只用 WhatsApp。

后来想加 Telegram。我以为要改很多配置。

结果只需要：

```json
{
  "channels": {
    "telegram": {
      "botToken": "xxx"
    }
  }
}
```

加一个 Token，就能用了。

**AI 的行为、记忆、工具，全都自动适用于新平台。**

### 这是怎么做到的？

**【画面：适配器架构】**

答案是 **Channel Adapter（通道适配器）**。

**【画面：翻译官比喻】**

每个平台的消息格式都不一样：

```javascript
// WhatsApp 的消息
{ remoteJid: "86138xxx@s.whatsapp.net", message: { conversation: "你好" } }

// Telegram 的消息
{ chat: { id: 123 }, text: "你好" }

// Discord 的消息
{ channel_id: "456", content: "你好" }
```

但经过 Adapter"翻译"后：

```javascript
// 统一格式
{ channel: "whatsapp", sender: "+86138xxx", text: "你好" }
{ channel: "telegram", sender: "123", text: "你好" }
{ channel: "discord", sender: "456", text: "你好" }
```

**【画面：架构图】**

```
WhatsApp ──→ [WhatsApp Adapter] ──┐
                                  │
Telegram ──→ [Telegram Adapter] ──┼──→ 统一格式 ──→ Agent
                                  │
Discord  ──→ [Discord Adapter]  ──┘
```

核心代码**只认识统一格式**。

它不知道消息是从 WhatsApp 来的还是 Telegram 来的，也不需要知道。

这就是**抽象的力量**。

新增一个平台？写一个 Adapter 就行。核心代码**一行不用改**。
